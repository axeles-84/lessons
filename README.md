5)Вопрос №5
Pull удобен для стабильных, предсказуемых инфраструктур с централизованным управлением и хорошей сетевой доступностью.

Push лучше подходит для динамических, распределённых, эфемерных сред, а также для событий и короткоживущих процессов.

На практике часто используют гибридные схемы: например, pull для инфраструктурных метрик и push для событий, логов или serverless-функций.

6)Вопрос №6

| Система | Основная модель | Push | Pull | Комментарий |
|---------|----------------|:----:|:----:|-------------|
| **Prometheus** | Pull | Да (Pushgateway) | Да (основная) | Сбор через scraping; remote_write — отправка во внешнее хранилище |
| **TICK** (Telegraf + InfluxDB) | Push | Да (основная) | Ограниченно | Telegraf сам отправляет метрики; InfluxDB 2.x умеет scrape |
| **Zabbix** | Гибрид | Да (активные проверки) | Да (пассивные проверки) | Оба режима равнозначны |
| **VictoriaMetrics** | Гибрид | Да (приём данных) | Да (scraping) | Совместим с Prometheus, принимает remote_write |
| **Nagios** | Pull | Да (NRDP) | Да (основная) | Активные проверки — pull, NRDP — push |
